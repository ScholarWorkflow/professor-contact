# 第五阶段原生委派

当前安装目标为 Codex 且用户要求执行第五阶段时，遵守本说明。

全部合法教授的 `owner_input_file` 写完后，下一步直接使用当前会话公开的原生 `spawn_agent` 工具，把每位合法教授分别委派给已安装且名称完全匹配的 `professor-contact-email-generator`。按当前会话实际提供的工具接口调用，不搜索 `ALL_TOOLS` 或通用工具目录，不使用 V1 工具发现，不探测命令行工具，不模拟委派，不启动另一个命令行程序，也不另发 `/eval` 请求。

每条子任务消息只包含该教授的 `owner_input_file` 绝对路径和该教授的业务约束。不得把业务字段抄入消息，也不得附加协调者的等待、路由或调用方指令。必须通过原生委派动作选择准确命名的代理；只在文字中提到代理名称不算委派。

等待每个已实际启动的子任务返回最终业务结果，并先消费这些结果，再重建总览。若真实原生调用返回工具或角色错误，为受影响的教授记录该实际错误；只有调用真实返回错误时才能报告委派失败。

若存在合法教授但没有对应子任务实际启动，报告“未委派”，停止正常总览和完成报告，说明教授核验、生成及校验尚未开始；确认没有读取者后清理本次请求文件。不得根据工具列表中未显示工具推断工具不可用，也不得声称业务已完成。若只启动了部分子任务，等待所有已启动任务结束，再根据实际本地状态重建一次总览，并报告各教授的真实结果和未启动教授的实际错误。

只清理本次请求中由协调者负责的文件；子任务仍在读取时保留文件。清理失败作为单独错误报告，不改变已完成教授的业务结果。
