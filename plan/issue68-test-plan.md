手册交付时重点核对：提示已按第4节修正；程序引用的是修复后的产品及第38版方案；读取本计划新路径的所有接线已更新；缓存失败保留分支与现有证据一致；分配及清理观察不把等价命令组织当作产品义务。须保存实际执行与方案的摘要关系，不要求历史记录摘要等于第38版。

## 6. 正式执行顺序与直接证据

以下是本计划要求的完整动作顺序；命令、安装接线和目录来源由本地测试工程师落实到同目录手册，独立第二关口冻结后执行者不得临场改测。不得只完成其中部分便宣称整例通过。

| 顺序 | 动作、来源及必须保存的事实 | 停止或判定边界 |
| --- | --- | --- |
| 0 | 固定产品修复、计划、手册、测试源码、共享及服务版本；独立第二关口通过；取得新运行执行授权；完成全部仍必要预检和同根目录核对 | 任一项未完成，不发送正式请求 |
| 1 | 准备第4节固定输入及独立预期，保存包、选择、结果文件、模板、状态及保护文件前记录 | 输入或独立预期不合法，停止准备；不预分配或代做交接 |
| 2 | 核对正式干净安装、空输出、消费者、请求缓存、传递位置及服务前记录；实际入口与固定源码关联 | 安装、版本或隔离前提不满足为 `CASE_NOT_STARTED` |
| 3 | 通过现有评估服务在正式消费者发送新运行的唯一请求；保存实际请求、完整响应、根线程、轮次及运行代次 | 请求发送为 `CASE_STARTED` 边界；之后不重发完整请求，不用新评估代替委派 |
| 4 | 根代理实际只读发现，合法教授与坏包独立；保存正式根线程命令及结构化返回 | 有效业务越界为失败，观察缺失或损坏分别分类 |
| 5 | 根代理一次完整确定性分配；保存实际参数、返回及顺序；路径取真实发现原值，选择与独立预期逐字段比较 | 有效证据确认改写路径、追加/部分/重试分配、错归属或业务早于分配完成为失败 |
| 6 | 按教授分别正式委派，等待真实结果；线程身份来自共享适配器正式关系 | 不从角色自述、提示、零条关系或诊断消息推断产品委派故障 |
| 7 | 各教授正常解析本次自己的交接一次；固定捕获复制同对象并调用原安装程序；关联文件、教授、调用及运行 | 有效数据含兄弟教授、全局结果表、错误本教授结果路径或错选择为产品失败；捕获缺失或无效另分类 |
| 8 | 首次实际 `stage5-plan` 不带 `--result`、`--choices`；保存实际字符串数组参数、原始标准输出、解析结构、退出码与首次核验值 | 错包、错编号、禁止参数或业务结果不符须以真实调用证据判失败，命令文字不能冒充实际参数 |
| 9 | 教授终态按固定早停约定保存；根代理等待并逐教授消费真实最终回执，原样保持 `professor_dir/status/reason_code` | 有效结果与预期不同或消费改写为失败；缺少可关联回执为观察阻断，多个冲突结果为无效证据 |
| 10 | 消费两位教授结果后独立总览一次；保存真实总览调用及完整返回；根最终消息分别原样报告教授与总览对象 | 有效证据确认提前/重复总览、结果改写或漏报为失败；包装键不是验收条件 |
| 11 | 请求及读取者结束后保存同范围后记录，核对全部传递物缺席、保护数据及教授状态；另记请求缓存与服务隔离收尾 | 残留、跨教授写入、保护数据变化或清理改写结果有有效证据即失败；观察缺口不覆盖已确证失败 |

每次正式运行分别保存产品提交、测试提交、计划和手册摘要、判定程序摘要、共享提交及干净状态、安装记录和 `manual_patch: no`、服务版本、实际配置、运行编号。原始响应及本机目录不公开；仅提交必要脱敏结果和摘要。证据副本不能被业务清理删除，临时脚本及预检产物不得提交或推送。

正式归属沿用共享适配器@16：`dispatch.thread_relations` 的 `tool=spawnAgent`、根 `sender_thread_id` 确定正式根子关系；`subAgentActivity` 仅唯一关联线程与 `agentPath`，不创建所有权。消费由当前根轮次合法 `FINAL_ANSWER` 回执与子线程原始最终结果对应，不由等待、自述或 `child_thread_reads` 替代。请求、线程、轮次、运行代次、调用和事件顺序须一致；运行代次值与 JSON 类型都比较，整数、字符串及布尔值不能相互转换。只取当前运行根线程的唯一最终业务消息，不从历史轮次或诊断补缺。

教授实际输入证明连接根分配对应项、本次交接文件、同次只读解析对象、同对象驱动的真实调用。固定信封保留 `pc68_fixed_capture`、`pc68_actual_input_observation`、`stage5_invocation`、`stage5_raw_stdout`、`stage5_process`、`stage5_plan`、`return_code`，以相同 `capture_id` 和正式调用关联。原始标准输出与解析对象必须一致。预期清单、命令字面量、事后重读、最终结果和加密消息都不能替代实际输入。

选择按字段和值比较，路径和编号按原字符串比较，不要求 JSON 缩进、键顺序或换行一致。首次实际参数禁止项与观察缺失严格分开；整项 `stage5_invocation` 缺失为观察阻断，对象存在但必需参数损坏为无效证据，真实参数确证违规为产品失败。

## 7. 生命周期及六终态

生命周期继续使用 `collect_before`、`bind_before`、`collect_lifecycle` 和 `verify_bound_lifecycle`：请求前完整记录绑定实际请求，中间以真实分配返回、教授正常读取或可归属交付证明实际形成与使用，请求和读取者结束后取得完整后记录。观察根为本次业务根、正式消费者及唯一传递根，不沿符号链接扩展，不扫描主目录或其他请求。

`snapshot_tree` 保存全部相对路径、文件字节数与摘要、目录、符号链接目标和根存在状态。正常链必须证明传递文件已清理且教授结果、旧文件、其他请求合成保护数据和安装产物未变；仅本例获准的总览派生变化可认可。不得只检查成功读取的文件，已形成但未交付的本请求文件也须依据实际归属检查。未知条目不能按后缀猜用途；归属或观察无法确定时不能写完整清理通过。

原始选择由真实分配读取证明，完整分配文件由正式成功返回及源码写入关系证明，交接由实际正常解析证明。最终缺席结合独占范围、没有测试替产品清理、实际使用及结果消费顺序归因产品清理；不要求特定创建、写入或删除事件。合法早停未产生后续教授选择或结果传递文件时不补造。缓存由测试运行器拥有，产品传递物由产品各负责者拥有，两者的清理问题分别保存。

| 终态 | 机器结果及条件 |
| --- | --- |
| `PASS` | 全部本例负责事实有直接、有效、可归属且一致的证据，禁止副作用检查完成 |
| `FAIL` | `FAIL_PRODUCT`；有效直接证据确认产品可控制行为违反冻结要求 |
| `BLOCKED` | 保留外部阻断标签或 `BLOCKED_OBSERVABILITY`；有效执行已开始，必要事实受外部运行或观察条件阻挡，尚无已确证产品违规 |
| `NOT TESTED` | 路径未形成且不是产品违规、外部阻断或测试缺陷；合法早停后未发生业务另记范围，不能要求其发生 |
| `INVALID_TEST_EXECUTION` | 执行、前提或证据污染、矛盾、损坏或无法可靠归因；观察损坏可用原 `INVALID_EVIDENCE` 标签 |
| `CASE_NOT_STARTED` | 未越过请求发送边界；例如未冻结、未获执行授权、安装失败或版本/隔离不符 |

在有效证据已经确证产品失败后，其他教授缺观察、回执缺失、生命周期缺证及缓存清理失败不得将整例降为非失败。清理异常附加记录，保留原失败原因和机器事实。没有已确证失败时，缓存清理未确认按固定执行器的无效执行分支处理，不宣称缓存完整清理；产品残留仍依据产品归属证据另判。真正污染使产品事实本身不可归因时先按证据有效性处理，不捏造产品失败。

本地测试工程师核对最终写出结果的所有收尾路径，不只核对中间判定器；用独立已知有效失败随后清理失败的最小样例确认最终仍为 `FAIL_PRODUCT`。基线已有两项针对性验证可按当前源码复用，不重复制造运行请求。
