# 第66号议题／第73号拉取请求完整执行计划（第十六版）

计划版本：`issue-66-plan-r16-2026-10-09`。

审核状态：专用计划审核已通过，记录见[第十六版执行计划审核](issue-66-execution-plan-review.md)。

目标仓库版本：`93ee2331ff927486fa84d306bb9de9a77a1e3f33`。本版完整取代第十五版执行计划，合并其仍有效决定，并落实验收决定人2026年10月9日对校验结果交接的调整：校验文件是唯一正式原文；校验子代理最终消息只报告本轮写入结果，不再承担第二份校验原文，也不再要求与文件逐字节相同。

## 1. 正式需求、范围与非目标

- 原需求继续采用第一关口第六版 `issue-66-gate1-r6-2026-10-05`：第三阶段每位教授使用自己的正式状态，推进教授甲不得被乙、程序总览或共享投影异常阻塞；第48号议题不是实施、测试或合并前提。
- 2026年10月9日验收决定人明确删除“校验子代理最终消息与校验文件逐字节相同”的要求。正式校验结果只以固定写入入口创建的校验文件为准；最终消息用于报告写入是否完成，不作为保存或记录入口的结果来源。
- 保留教授姓名唯一的范围约定，不增加同名支持、消歧或相关测试。
- 非目标仍包括其他阶段的独立状态改造、断电或强制终止时的跨文件持久性、同一教授的多个独立并发写入者、一般写入覆盖及非 Codex 运行证明。

## 2. 正式状态及责任

1. 教授目录内的 `套磁候选状态.json` 是第三阶段正式状态；`套磁想法候选.md` 是本地候选稿；程序总览只从已提交状态派生。
2. 生成子代理负责生成或修正候选，调用产品入口保存候选稿和正式状态，并返回本次教授调用的凭据。
3. 校验子代理负责阅读候选稿、形成校验结论，并把完整结果对象交给固定写入入口。固定写入入口负责结构检查、确定格式和排他写入指定文件。
4. 固定写入入口成功创建的校验文件是唯一正式校验原文。根代理只使用准备入口返回的交接信息调用保存及记录入口，不从子代理最终消息复制、解析或重建校验结果。
5. 带 `output_file` 的校验子代理最终消息只返回第6.2节规定的完成报告，不包含 `files`、`verdict`、`issues`、`notes` 等校验正文。未带 `output_file` 的旧只读调用继续返回完整校验对象。
6. 根代理负责准备交接、等待并消费子代理完成结果、保存校验文件、记录轮次、按记录结果决定修正或停止，并在终态后尽力重建一次总览。

## 3. 教授本地提交

`stage3-finalize` 的业务读取只限当前教授输入包、旧候选状态、当前教授受管候选稿、本轮生成结果及固定资料。其他教授状态、程序总览和 `_contact_projections.json` 都不得成为本地提交前提。

本地候选稿和候选状态先准备完成，再依次安装候选稿、候选状态。候选状态安装成功是业务提交点。提交前普通异常恢复两份旧文件；提交后的清理或总览失败不得撤销已提交状态。当前教授自己的受管候选稿存在人工冲突时继续拒绝覆盖。

临时调用凭据、交接元数据和校验文件都不是候选正式状态，不得改变候选状态结构、候选与方向及跨方向组编号、缺口引用、资料与输入指纹或已有校验记录沿用规则。

## 4. 派生总览和第四阶段

`stage3-rebuild-overview --program-root` 只从各教授目录内已经提交的 `套磁候选状态.json` 生成总览。候选稿只提供链接目标，不提供候选机器事实；总览与 `_contact_projections.json` 都不是正式状态。

教授规范目录身份贯穿普通方向、跨方向组、总览链接和第四阶段读取。不同教授即使方向或组编号相同，也不得合并。重建排序稳定；删除总览后可仅凭正式状态恢复相同业务行和链接。

一个现存状态损坏、旧身份零匹配或多匹配、总览人工冲突或写入失败时，不发布部分总览，也不修改教授本地状态和候选稿。旧身份只有唯一精确匹配时才迁移身份，候选事实保持不变。

第四阶段继续只消费明确指定教授目录内的正式候选状态，不从第三阶段总览、调用凭据或校验交接文件读取候选事实。

## 5. 调用凭据和修正范围

首轮 `stage3-plan --capture-invocation <独占目录>` 在输入验证成功后，从实际解析参数生成 `stage3-invocation.json`，返回规范文件路径与文件摘要。独占目录必须由系统临时目录创建接口排他分配；一次业务调用只捕获一次，正常的新调用重新分配目录。

`stage3-plan` 和 `stage3-finalize` 通过 `--invocation-file` 与 `--invocation-sha256` 消费同一凭据。凭据方式与重新传入教授、资料、程序根、刷新范围、跳过及跨方向等来源参数互斥。凭据损坏、摘要不符、教授归属不符或资料来源变化时，在写入候选和正式状态前拒绝。

修正工作集合只来自本教授正式状态中已经记录的校验问题：方向集合和跨方向组集合不得被首轮选择、跳过或组请求再次过滤；组问题不得扩大为全部参与方向；文件问题按实际渲染对象展开。修正结果只在旧集合原位置替换，未涉及方向、组、候选和校验记录保持不变。

普通生成继续保留原选择、跳过和未请求组删除语义。旧显式修正继续保留原准入和筛选语义，但成功提交同样保留未涉及方向和组。

## 6. 校验文件的生产与交接

### 6.1 准备

根代理使用本教授首轮返回的调用凭据执行：

```text
stage3-prepare-validation --invocation-file I --invocation-sha256 IS --round N
```

准备入口核对教授、调用、候选稿和轮次，排他创建本教授、本次调用、本轮独占的交接目录，并返回交接文件、交接摘要、指定输出文件及候选稿路径。同一调用同一轮重复准备继续拒绝；相同输入的新调用不得与旧调用碰撞。

### 6.2 固定写入

校验子代理阅读准备结果指定的候选稿，形成一个完整校验结果对象，并调用：

```text
stage3-write-validation --output-file O --result-json <完整校验对象>
```

固定写入入口在创建文件前检查参数和结果结构；合法通过、轻微问题和阻断问题都可作为完整结果写入。入口使用确定格式生成一份结果字节，排他创建指定文件，设置受限权限，读回核对后返回成功。既有文件、符号链接、非法对象、写入或读回失败均返回错误，不覆盖旧目标。

批量映射先检查所有教授与目标，再把各教授完整结果分别写入对应文件。后项失败时停止，保留已经完成的文件，只清理本次未完成目标，不反转其他教授已经提交的正式状态。

校验子代理不得自行编写临时文件程序，不得修改候选稿、输入包、正式状态或总览。最终消息只报告固定写入是否完成及必要引用；不得把消息正文当作正式校验结果，也不得要求消息复制文件字节。

带 `output_file` 的调用只发送一条 JSON 完成报告。单文件和批量统一使用 `output_files` 数组，路径顺序与本轮输入的候选稿顺序一致：

```json
{
  "result": "ok",
  "write_status": "written",
  "output_files": ["<指定输出文件绝对路径>"]
}
```

固定写入未成功时返回：

```json
{
  "result": "error",
  "write_status": "failed",
  "output_files": ["<本轮指定输出文件绝对路径>"],
  "reason_code": "<固定写入入口返回的原因码；没有原因码时为 validation_write_failed>"
}
```

完成报告不得增加校验结论或问题字段。成功报告只证明子代理已完成固定写入调用；文件存在、内容合法、教授与轮次绑定仍由后续保存和记录入口判定。失败报告后立即停止，不得运行保存或记录。

### 6.3 保存和记录

固定写入成功后，根代理执行：

```text
stage3-save-validation --handoff-file H --handoff-sha256 HS
stage3-record-validation --handoff-file H --handoff-sha256 HS --expected-validation-sha256 VS
```

保存入口从交接元数据取得固定写入源文件和本轮保存目标，原样复制文件并返回保存文件与摘要。记录入口读取保存文件，核对教授、调用、候选稿、轮次及预期摘要，解析同一 JSON 对象，将本教授轮次、问题和终态写入正式状态。摘要用于绑定保存与记录实际消费的文件，不用于比较子代理最终消息。

任何准备、固定写入、保存或记录失败都必须在下一依赖动作前停止。根代理不得从最终消息补写文件，不得修整、重排或重新序列化文件来求通过。

## 7. 两轮推进和停止

第一轮记录返回无需修正时直接进入终态；返回 `needs_correction=true` 且尚未终态时，只委派一次生成修正，继续使用同一调用凭据和已记录校验文件。修正保存成功后准备第二轮，再执行固定写入、保存和记录。

第二轮记录后必须停止，不得派发第三轮。第二轮通过或 `fail_after_2_rounds` 都是合法流程终态；候选内容是否通过校验应单独报告，不能把合法失败结论当作入口执行失败。

终态后只尽力执行一次总览重建。总览失败只报告展示问题，不重新生成候选、不撤销教授正式状态，也不改变校验内容结论。

## 8. 产品修改位置及顺序

1. 更新校验代理源说明，删除“最终消息必须重复完整校验 JSON 并与文件逐字节相同”，按第6.2节返回固定字段的完成报告；未传指定输出文件的旧只读调用保持原返回方式。
2. 更新技能中的 Codex 第三阶段流程及相关工作流说明，明确文件是唯一正式校验原文，根等待子代理完成后只核对完成报告并按准备结果执行保存和记录，不消费最终消息中的校验正文。
3. 保持 `contact_state.py` 的固定写入、准备、保存、记录、凭据、修正集合和两轮状态逻辑；只有源说明与实际入口不一致时才作必要同步，不为消息格式增加第二套结果载体。
4. 同步 Codex 实际安装消费的代理与技能内容，避免源文件和已安装指令继续要求旧的重复正文。其他运行时不属于本次实施范围。
5. 产品修改完成后，由测试工程师按当前必测清单分析影响；复用未受影响的既有结果，只对完成报告及其直接影响安排一次当前实现的E组运行，不重开教授本地提交、总览、凭据、修正集合和第四阶段的确定性测试。

## 9. 方案选择与影响

所选方案以固定写入文件作为唯一正式校验原文。另一种方案是让最终消息继续重复完整 JSON，再用 JSON 结构比较忽略空白；该方案仍保留两个内容载体，根容易误用消息重建文件，因此不采用。

- `intended_change`：删除最终消息与文件逐字节相同的要求；最终消息改为完成报告；文件继续承担校验结果生产、保存和记录。
- `preserved_behavior`：校验规则、合法结果结构、教授与调用及轮次绑定、文件原样保存、记录状态、修正范围、两轮上限、总览重建和旧只读入口保持。
- `approved_behavior_change`：来源为验收决定人2026年10月9日本轮明确指示。
- `prohibited_side_effect`：不得降低校验内容标准，不得忽略或改写失败结论，不得让根从消息重建结果，不得删除文件完整性及教授绑定检查，不得新增模型请求求通过。
- 未解决影响：无。带 `output_file` 时的最终消息字段已由第6.2节固定；实现者不得另加完整校验正文或自创第二种成功报告。

## 10. 代表性反例和失败处理

- 消息传输删除末尾换行，但固定写入文件完整：流程继续按文件保存和记录，消息格式差异不构成业务失败。
- 固定写入成功后文件在保存前被替换：保存或记录的绑定检查拒绝，不能凭消息内容补救。
- 子代理报告成功但固定写入失败或文件不存在：根在保存入口失败后停止，不得把报告当作成功证据。
- 完整校验结论为失败：仍须保存和记录；只有记录结果决定是否修正和是否终态。
- 第二轮仍失败：记录 `fail_after_2_rounds` 后停止并重建一次总览，不派发第三轮。
- 其他教授文件或程序总览异常：不得阻塞当前教授已经合法完成的本地提交。
