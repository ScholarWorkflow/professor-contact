## 固定写入入口的证明

校验者先形成完整 `result`、`files[]`、`notes` 对象，将它作为单个 `--result-json` 参数交给固定命令。固定命令首次序列化并返回成功字节；校验者最终业务消息逐字复用成功标准输出。参数对象与最终结果比较语义及全部扩展字段；标准输出、输出文件、最终消息及后续保存输入比较原始字节。**不要求写入前已经存在最终业务消息，也不要求输入参数的空白排版与输出相同**。

| 证明项 | 最小正反对照与判据 |
| --- | --- |
| 完整合法结果 | 单文件和批量正常成功；UTF-8、扩展字段、完整对象均保留。分别提供合法 `pass`、`pass_with_minor`、`fail` 校验结果，问题字段、计数和结论一致；后三者是校验业务结论，合法对象都必须写入成功，不能把 `fail` 当作写入命令失败。至少以一个合法有轻微问题、一个合法有阻断问题的对象证明。 |
| 非法结果先拒绝 | 空输入、重复键、非有限数、顶层非对象、缺失或错误类型的 `result/files/notes`、空文件集、没有候选、相对文件路径、未知产物或结论、缺失或错误类型字段、非法问题严重级别和位置、超长引文、布尔或非整数计数、计数与问题不一致。结构化错误、非零退出，所有输出保持不存在；受保护业务文件不变。合法问题正例与非法问题反例成对，防止一律拒绝造成误判。 |
| 单文件与批量映射 | 单文件只用 `--output-file`，完整结果只有一个候选；真实准备返回路径原样传入。批量只用 `--output-map-json`，候选与准备输出一对一，全部文件保存同一完整结果。缺项、重复候选、额外候选、重复输出、非法映射字段、相对输出均先拒绝，不产生任何输出。 |
| 路径与排他创建 | 绝对路径、父目录已存在；拒绝缺父目录、已有目标和符号链接，不创建父目录、不覆盖旧内容或链接目标。批量第二目标冲突时，第一目标也不创建，已完成路径数组为空。成功文件模式为 `0600`，排他创建及同一文件描述符回读由确定性操作观察证明。 |
| 同一输出字节 | 实际退出码为零，标准输出非空；单文件与标准输出逐字节相同，批量每个文件与同一标准输出相同；解析后包含完整结果及扩展字段。候选稿不被写入命令改动。 |
| 部分失败 | 在第二个批量文件注入部分写入故障；非零退出、`validation_write_failed`，第一个完整文件保留并列入 `completed_paths`，只清理本次未完成第二文件，不回滚已完成文件。错误报告与实际存在性、字节一致。 |
| 调用者停止与只读兼容 | 准备 → 校验者固定写入 → 根保存 → 根记录。非零退出、结构化错误、缺失或不完整标准输出、输出字节不符时，立即按已有错误约定报告并停止，不保存、记录、派发依赖修正或新生成。未提供 `output_file` 时保留原有只读返回，不调用写入命令。 |

正式参数必须来自真实准备返回值及该校验者完整结果，不能由根调用者拆分、重建或重新序列化。批量映射保留每个候选与准备返回路径的关联。测试构造对象可以证明固定命令语义，不能证明真实校验者值源。

## 正式运行必须观察的事实

正式必需模型用例仍只有 `S3-RT-CODEX-1`。沿批准输入运行根任务：首轮生成与校验，必要时一次按记录问题精确修正与校验，终局重建总览一次。正常终态对应根直接派发两个或四个子任务，不允许嵌套、根外业务子任务或第五个子任务。故障中断可只形成合法前缀，不能因未完成而假定四个任务应全部存在。

原生事件按机器字段及关系判断根与子任务归属，使用契约规定的 `sender_thread_id` 等实际字段；请求名称或已加载代理名称只作诊断，不能单独证明调用归属。完整输入、实际参数、工具开始与完成、退出码、标准输出、消息顺序、文件观察都关联同一运行与轮次。

必须证明：实际首轮捕获返回凭据被后续消费；校验者构造完整结果并调用固定写入入口；指定输出等于准备返回值；成功标准输出、输出文件、校验者最终消息及保存输入是同一原文字节；保存和记录完成后才派发修正或终态重建。运行采集应覆盖临时交接目录，保留保存前输出文件字节、模式及必要存在性观察，避免保存后文件消失造成空白证据。

原生轨迹中的固定命令身份、参数、归属、顺序和实际输出关联，结合确定性测试证明排他创建、同一文件描述符回读及故障清理。无需每个内部系统调用都在原生事件重复出现；但不能只凭静态约定或 `fileChange Add` 推断实际输出字节、此前不存在、模式或生产者身份。

停止验证区分业务续行与唯一结构化错误报告：错误报告及根接收事件可以存在，错误后的保存、记录、修正或新生成不允许。正确停止不等于业务完成。总览失败不反转已提交的教授终态；有完整可归因事实才判断产品失败，轨迹缺失不能臆造产品行为。

保留全部原始标准输出、标准错误、退出码、结构化套件条目、事件、前后状态、判定输入输出及样例账本。使用 `jq` 解析 JSON/JSONL、`yq` 解析 YAML/TOML、`xmllint` 解析 XML；按字段、事件类型、编号和先后关系判断，不扫描日志关键词推测条目或归属。套件至少有实际执行条目、身份唯一且报告自洽，条目数动态记录，不设固定总数。新套件接入已有结构化报告通道，不能只留 `unittest -v` 文本。

| 终态 | 适用边界 |
