## 执行准备与结果复用

本文件是完整测试设计。测试计划工程师负责目标与检查方式；本地测试工程师在**本文件**补齐每项实际采用的断言或直接执行命令、合成输入、配置来源、输出位置和清理步骤，再提交第二关口。尚未补齐的执行步骤不推定可执行，不把补齐步骤转交用户猜测。本轮只生成和审核设计，不运行正式测试。

优先复用仍适用的安装和结果。由本地测试工程师核对[历史结果来源](https://github.com/ScholarWorkflow/professor-contact/pull/73#issuecomment-5981805377)和仓库 `test-plan/issue-66-results-history.md`、`test-plan/issue-66-runtime-attempts-20261007.md`：能覆盖当前目标且行为未变的结果记录复用来源；需要复验时说明受影响行为。旧212项通过、旧安装成功均不自动等于当前14项全部通过；提交编号变化也不使未变结果失效。被删除的测试代码不默认恢复整套，只补缺少的清单内检查。

确定性测试在生产者仓库内执行；模型运行从独立消费者目录开始，采用支持的安装路径。当前安装仍适用时直接复用；必须测试改变后的产品而安装已失效时，按支持路径为该产品版本创建干净消费者，禁止复制文件或手工修补。共享夹具只准备隔离环境和配置，不代替产品行为。

Codex 使用既有评估服务，不启动、停止或重启服务；实际请求按工作区 `eval-server/README.md` 及 `eval-server/docs/appserver-migration.md` 接线。端口从 `direnv exec .` 取得，默认配置由共享夹具的版本化配置文件提供；采用共识规定的模型与推理设置，不在请求重复覆盖。准备步骤只检查命令、必要依赖和状态隔离，复用有效预检；不新增事件来源认证或通用证据能力检查。

临时输入、实际配置及必要原始输出使用仓库外独立 `/tmp` 目录，隔离会话、可写资料、端口和输出；不得连接生产资料、浏览器状态或无关进程。正式计划和必要脱敏结果入库，原始敏感材料不上传公开记录。需要机器检查的结构化输出用 `jq`、`yq` 或 `xmllint` 解析必要字段；不默认新增采集器、判定程序、完整轨迹或逐项证据账本。

## 失败、重试与完成

- 每个正式模型场景最多一次请求，不自动重试。外部额度、连接、服务、线程或观察故障记为无法判断并停止受影响项；继续其他项。恢复后需要新尝试时，先补齐原因、状态清理、保持不变的参数及次数约定并确认步骤，不把换输入或模型记为同条件重试。
- 业务失败不得重新采样求通过；步骤错误先停止并修正，产品问题交实现负责人。保存所有正式尝试，后续清理或网络错误不覆盖已确认业务失败。
- 结果区分通过、业务失败、无法判断、未执行。已有记录遗漏时先取得原记录，待补不直接判产品失败，也不批准缺失结果。
- 仅复核修改影响的目标。禁止默认增加全仓回归、全量调用留存、同步快照、运行身份认证或专用判定平台。
- 第一关口核定上述必测清单；第二关口核定补齐的执行步骤可运行且无超范围要求；第三关口核定逐项结果当前有效。必测项全部取得有效通过、范围内缺陷已处理后结束；本计划不作合并批准。
