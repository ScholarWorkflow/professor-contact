1. 共用工具保留在本仓库 `.apm/skills/professor-contact/tests/`，仅用于测试，使用虚构数据。
2. 抽取 `runtime/prepare_issue53_stage4_fixture.py` 与 `runtime/prepare_issue55_stage3_fixture.py` 的空目录准备、文件写入和文件摘要计算，两个既有入口实际复用。保持原命令参数、返回对象、错误类型、生成文件内容、摘要及各自验收要求兼容。
3. 拒绝生产者检出目录及其子目录、非目录目标和已有内容的目标；拒绝时不覆盖或删除原有文件。不同运行使用独立目录。共用工具不启动浏览器、外部服务或代理，不修改业务程序。
4. 提供仓库内说明，区分共用准备工具、既有执行与判定入口、问题专属样例和断言。复用 `gate2_evidence.py` 的结构化结果，产品失败不能当成准备失败，空执行不能通过。

首批只迁移第 53、55 号两个准备入口。不迁移其他历史准备程序，不改变业务工作流、代理配置、教授状态文件或外部工具。

## 方案

新增 `tests/runtime/fixture_support.py`，只提供以下共用能力：

- 解析并检查样例根目录是否位于生产者检出目录之外；
- 拒绝非目录和非空目录；已有空目录保持原样，缺失目录按需创建；
- 检查第 53 号两个根目录不得相等或互为祖先；
- 检查清单输出位于生产者检出目录之外、目标尚不存在，并且不与已知样例文件路径相同；
- 提供保持既有格式的文本和 JSON 写入；
- 清单使用排他创建，目标出现时拒绝覆盖；
- 提供文件 SHA-256 计算；
- 记录目录是否由本次调用创建及准备时的文件系统身份，只用于第 53 号失败回滚时避免删除错误目录。

第 53、55 号入口继续负责各自的业务数据、文件布局、清单字段和返回对象。共用模块不包含议题专属业务断言。

运行目录由调用方或测试设施分配。每次运行使用自己的独立临时目录，例如由 `mktemp` 或 `TemporaryDirectory` 产生带随机后缀的目录。共用工具不负责跨运行的目录分配。

## 写入与兼容要求

R2 的兼容范围覆盖合法输入：

- 原命令参数不变；
- 返回对象和错误通道不变；
- 成功生成的文件内容和 JSON 格式不变；
- SHA-256 摘要算法不变；
- 第 53、55 号既有业务验收要求不变；
- 直接执行脚本和按文件路径加载模块两种调用方式继续可用。

按 R3 拒绝以下输入：

- 样例根目录位于生产者检出目录或其子目录；
- 样例根目录是普通文件或其他非目录对象；
- 样例根目录已有内容；
- 第 53 号两个根目录相等或互为祖先；
- 清单输出位于生产者检出目录或其子目录；
- 清单输出已经存在；
- 清单输出与本次已知样例文件路径相同。

预先能发现的非法输入在写入样例前失败。清单实际创建时再次使用排他创建；如果目标在此前出现，则拒绝覆盖，已经生成的样例保留用于诊断。

## 第 53 号目录回滚

第 53 号依次准备程序根和资料根。

- 第一个根目录原本存在且为空：保持原目录；第二个根目录准备失败时不删除第一个目录。
- 第一个根目录由本次调用创建：第二个根目录准备失败时，仅当文件系统身份仍与准备时一致才删除第一个目录。
- 身份已经变化：停止删除并返回错误，避免删除后来替换到同一路径的目录。
- 两个根目录都准备完成后，后续写入失败保留已写出的部分样例，不做递归清理。
