## 1. Approved requirement and historical relationship

Keep the normal **two-round default**. After a failed exhausted Stage 2 or Stage 3 validation cycle, the human may explicitly authorize a positive integer number of additional rounds. Grants accumulate: +2 makes the current limit 4; another +1 makes it 5. Four is an example, not a cap. Do not choose a number on the user's behalf. Neither the coordinator nor validator may grant itself more rounds, reset an exhausted cycle, erase failures or treat authorization as passing validation.

This new user-approved direction replaces the incompatible fixed-limit decision only for the current Stage 2/3 continuation feature. [Issue77](https://github.com/ScholarWorkflow/professor-contact/issues/77) proposed default-three Stage3/5 and statistics, excluded Stage2 and rejected fourth-round continuation. It is historical context, not the current plan or a dependency. Do not edit that issue, silently implement its statistics, change Stage5, or import its older proof requirements. [PR107](https://github.com/ScholarWorkflow/professor-contact/pull/107) fixed-source owner protection remains intact; continuation expands available validation rounds, not what a generator may rewrite. [PR137](https://github.com/ScholarWorkflow/professor-contact/pull/137) does not grant new rewriting permissions. Source-evidence repair, display repair, Stage3 rerender and PR143 are separate features; no dependency on their merge.

## 3. Frozen interface and state design

### Human grant entry

Add `stage2-continue-validation` and `stage3-continue-validation`, each accepting `--professor-dir`, `--additional-rounds N`, `--authorization TEXT`, `--expected-round R`, and `--expected-state-sha256 SHA`. N must be a positive integer; TEXT records the user's actual explicit instruction, not an agent's rationale. R is the currently exhausted round the human was shown; SHA is the digest of that current stage state file (ordinary existing SHA-256, not an identity certificate). These proposed public entry names can be renamed consistently before implementation; semantics cannot be omitted.

The skill/coordinator must obtain an explicit human grant identifying the professor, stage and number after reporting the failed exhausted state. Generic 'continue' without a number is insufficient. Command input records this decision for practical accountability; it is **not cryptographic proof of human identity** and no authentication/provenance service is introduced. Agents must not fabricate authorization text, auto-default N or call the command as routine retry. The CLI cannot authenticate an arbitrary external shell caller; that trust boundary is stated rather than falsely certified.

The command validates the current professor-local state and existing render/input binding, current round == R and the exact current state digest == SHA, terminal failure at the effective limit, and actual blocking findings. Passing terminal, unstarted/malformed/stale states and wrong professor/stage fail without writes. Stage2 fixed-blocking findings remain source/generator-owner work: the grant cannot turn them into a narrative job. Such findings may remain registered while the operator gets an actionable owner response; no automatic repair is triggered.

### Minimal persisted continuation data

Keep data in the existing stage's professor-local validator block. Add a versioned continuation object with base_limit=2 and grants (old_limit, additional_rounds, new_limit, granted_at, authorization text, exhausted_round, expected_state_sha256). Effective limit is 2 + the valid grant amounts; validate arithmetic and sequence, never trust a caller-supplied absolute max. An absent object means the existing two-round policy. Each successful record of an actual validation round retains that round’s minimal result/issues, actual round, render/input bindings and raw report path/digest in the same validator history; subsequent record, correction carry and final PASS preserve it. Each grant also snapshots the just-exhausted result/terminal label before reopening failed scopes, without duplicating already-recorded round history. A failure at extended round3 therefore remains visible after round4 PASS. Do not invent missing past raw outputs; existing report files remain the evidence, and legacy history coverage is described honestly.

Perform all validations before one atomic state-file replacement. Operate serially within the existing professor-local workflow; compare the expected round and exact state digest again before commit, and reject detected drift. A grant is accepted only at the currently exhausted state; repeating the command immediately sees a reopened nonterminal state and cannot add twice. A later distinct exhausted state can receive another explicit grant with its own current digest; an old grant prepared for a previous cycle cannot apply even if the same professor again reaches round2. No cross-professor writes, global policy file, statistics database or automatic grant renewal.

The effective limit/actual round/remaining allowance and retained failed history are readable in command output and current state. No private event stream or separate ledger is required. Authorization/history are product state for this feature, not new evidence collectors.

### Reopen and advance without laundering failure

1. A grant retains the actual round R, prior raw report/issues and snapshots; restores pending **only from the recorded failed result**. Stage2 maps its persisted pending/results back to the existing correction owner logic. Stage3 restores failed direction/group scopes (including global findings already attached to their affected scopes) from terminal results. Passed scopes do not become correction targets.
2. Caller performs the existing scoped correction using the last raw validation report. No grant bypasses source guards, protected machine facts, manual-edit checks, or correction completion. Fixed source problems still go to their actual owner; generic continuation is not the source repair entry.
3. After successful correction, validation R+1 uses its own new output file and existing input/render binding. The record command accepts only the next actual round within effective limit. Retain history and grants through Stage2 refine-finalize and Stage3 carry; never reset to 0/1 during continuation. Expand existing Stage3 handoff round checks and CLI argument range together, not just MAX_ROUNDS.
4. Passing stops immediately. Failure below effective limit stays correction-required; failure at limit is terminal and awaits a new explicit human grant. No unvalidated tail correction after final failure. Return actual rounds and effective limit; do not infer success from pending emptiness.
5. Preserve legacy `fail_after_2_rounds` for an unextended two-round exhaustion. For extended cycles, use a generic `fail_after_max_rounds` plus actual `rounds` and `max_rounds` fields, not a misleading two-round label. Shared validators/readers must accept this only for Stage2/3 with valid continuation policy and matching actual exhaustion. Stage5 and its legacy `load_validator_results` contract remain unchanged. Update direct Stage2 preflight/legality and Stage3 overview/downstream consumers where they inspect these labels; never global-replace strings.
6. A genuine new source/generation follows existing normal invalidation/new-cycle logic, not continuation. Before replacing the current cycle, carry its existing history and final current snapshot to a retained history field in the same professor-local state. This is preservation only, not a new archive/statistics feature. New cycle starts default2 with no inherited grants; a new request cannot reuse authorization from a different cycle. Unchanged rerender/refine/time-only updates cannot masquerade as a new cycle to clear failure. Where current normal acceptance intentionally invalidates validation for real changed source, preserve the historical failure while current validation legitimately becomes unvalidated.

## 4. Compatibility, responsibilities and counterexamples

- Existing no-continuation records retain two-round behavior and terminal labels. An explicitly selected legacy terminal failure may receive a new human grant if its current binding and findings are valid; do not upgrade/reopen automatically. Missing required scope/evidence means normal repair/refresh, not fabricated history.
- The runner owns state/limits and errors. Coordinator owns asking and passing the user's grant; validators still report only, generators still repair only the permitted scopes. Codex/OpenCode instructions each keep their native delegation and wait/consume behavior, not new fixed topology/thread ceilings. The limit is business rounds, not concurrency.
- Alternatives: globally raising limit to 3/4 violates explicit human control/default2; clearing validator state loses prior failures; separate budget database duplicates state ownership. In-state additive grants plus existing correction loop are the narrow design.
- Representative counterexamples: a repeated command cannot double-grant the same already-reopened state; round R+2 without R+1 rejects; no-op rerender cannot reset counts; a passing result cannot be reopened for extra sampling; fixed-source errors do not become editable narrative; Stage3 global findings cannot disappear when rebuilding pending; new cycle cannot inherit old grant; old failures remain visible when later round passes.
- Approved behavior change: explicit human continuation beyond 2 for Stage2/3 only. Preserved: default2, raw report integrity, real completed-round counting, early pass, scope/identity, source protection, manual protection and normal owner handoff. Prohibited: automatic increase/reset, Stage5/default3/statistics, generalized auth/provenance service, new full-workflow tests.
- Unresolved critical design assumptions: none claimed about unavailable attachment code. Implementation still must wire all identified consumers; implementation existence is sequencing work, not prior proof of correctness.
